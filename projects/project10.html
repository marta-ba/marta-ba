The critical leak: Shipping → Payment

Of five funnel steps analysed across 13,000+ mobile sessions from the GA4 public ecommerce dataset, one transition dominates the revenue story: users who enter the shipping step fail to reach payment at a rate of 40% — the steepest single drop in the funnel.

At an average order value of €54.09, each percentage point of improvement at this step is worth approximately €4,300 in recovered revenue.

Priority Fix
Fix the Shipping → Payment wall

The Shipping → Payment step loses 3,164 mobile users — more than any other transition in the funnel. On mobile this step typically renders a long-form address + delivery-options layout followed by a slow-loading payment iframe. The combination of cognitive load and performance friction is a well-documented mobile conversion killer.

Recommended interventions:

  • Collapse shipping + payment into a single scrollable step (reduce context switches).
  • Lazy-load the payment iframe only after address validation, cutting perceived wait time.
  • Surface saved addresses and Apple Pay / Google Pay above the fold — one-tap acceleration for returning users.
  • Add a progress indicator: mobile users who see where they are in a flow show higher completion rates.
Business hypothesis: A +2 pp improvement in Shipping → Payment CVR (60.1% → 62.1%) would recover approximately €8,600 per cohort period at current AOV. A +5 pp gain reaches €21,500. These are conservative estimates based on the dataset's observed AOV of €54.09.

Methodology

Data source

BigQuery public dataset: bigquery-public-data.ga4_obfuscated_sample_ecommerce — a real obfuscated GA4 export from a Google Merchandise Store property.

Filtered to device.category = 'mobile' exclusively. Five GA4 events mapped to funnel steps: add_to_cart, begin_checkout, add_shipping_info, add_payment_info, purchase.

SQL — funnel view

-- Step 1: flatten events per user
WITH mobile_events AS (
  SELECT
    user_pseudo_id,
    event_name,
    (SELECT value.double_value
     FROM UNNEST(event_params)
     WHERE key = 'value') AS purchase_value
  FROM `bigquery-public-data.ga4_obfuscated_sample_ecommerce.events_*`
  WHERE
    device.category = 'mobile'
    AND event_name IN (
      'add_to_cart', 'begin_checkout', 'add_shipping_info',
      'add_payment_info', 'purchase'
    )
),

-- Step 2: pivot into one row per user
mobile_funnel AS (
  SELECT
    user_pseudo_id,
    MAX(IF(event_name = 'add_to_cart',       1, 0)) AS step_cart,
    MAX(IF(event_name = 'begin_checkout',     1, 0)) AS step_checkout,
    MAX(IF(event_name = 'add_shipping_info',  1, 0)) AS step_shipping,
    MAX(IF(event_name = 'add_payment_info',   1, 0)) AS step_payment,
    MAX(IF(event_name = 'purchase',           1, 0)) AS step_purchase,
    SUM(IF(event_name = 'purchase', purchase_value, 0)) AS revenue
  FROM mobile_events
  GROUP BY user_pseudo_id
)

-- Saved as view: `project.analytics_us.x_mobile_funnel`
SELECT * FROM mobile_funnel

Metrics derived

-- Step-level aggregation + business metrics
SELECT
  SUM(step_cart)                                              AS n_cart,
  SUM(step_checkout)                                          AS n_checkout,
  SUM(step_shipping)                                          AS n_shipping,
  SUM(step_payment)                                           AS n_payment,
  SUM(step_purchase)                                          AS n_purchase,
  SUM(revenue)                                                AS total_revenue,
  SAFE_DIVIDE(SUM(step_checkout), SUM(step_cart))           AS cvr_cart_checkout,
  SAFE_DIVIDE(SUM(step_shipping), SUM(step_checkout))       AS cvr_checkout_ship,
  SAFE_DIVIDE(SUM(step_payment),  SUM(step_shipping))       AS cvr_ship_payment,
  SAFE_DIVIDE(SUM(step_purchase), SUM(step_payment))        AS cvr_payment_purchase,

  -- Revenue at Risk = users_lost × AOV
  (SUM(step_cart)     - SUM(step_checkout)) * avg_order_value  AS rar_cart,
  (SUM(step_shipping) - SUM(step_payment))  * avg_order_value  AS rar_shipping
FROM x_mobile_funnel, totals

Relevance to conversion-focused roles
This project mirrors the "own the conversion funnel" requirement common in e-commerce analytics and growth engineering roles. It demonstrates end-to-end ownership: raw GA4 event data → SQL transformation → business metric derivation → actionable UX recommendation with a quantified revenue impact, all built on the GA4 + BigQuery + Looker Studio stack that is standard at scale e-commerce organisations.

Limitations & honesty

The dataset is obfuscated — user IDs and some values are anonymised, which may introduce minor counting artefacts (e.g. the Checkout → Shipping CVR slightly exceeds 100%, indicating cross-session event attribution quirks in the public sample).

Revenue values of 0.0 are present for some confirmed purchasers, likely due to obfuscation of order value. AOV is computed only over transactions with revenue > 0 to avoid deflation.

The Revenue-at-Risk figures are indicative, not a guaranteed recovery number. Actual uplift from UX improvements depends on implementation quality, device distribution, and market context.
